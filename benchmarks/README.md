# Reproducible synthetic benchmark

Run through `POST /v1/tenants/{tenant}/benchmarks` with `{ "seed": 42, "count": 100 }`, then retrieve/export the job. Count must be 2..1000. Every run records seed, synthetic model version, prices, runtime rate, OS/architecture, Go version, CPU count, scenario counts, and fixed observation time. Host model is explicitly not captured; record it in release evidence for controlled performance acceptance.

The held-out generator samples 11 named scenario distributions with a seeded PRNG and alternates complete/conditional profiles (an odd count gives complete one extra sample). The fixed eight-row planner tuning table is separate from the held-out generator. Correlated scenarios set SIM and device changes together. All strategies obtain the same immutable scenario observations anchored to the same evaluation timestamp. Use new held-out seeds when changing planner tuning; do not tune on reported evaluation results.

Comparators: full sequential fetch; full parallel fetch; competent number/SIM/device staged fetching; identical staged fetching with generated OPA final evaluation; OptiTrace's minimum-estimated-cost valid plan. The staged comparator is allowed all safe early exits. No speedup or savings is guaranteed; complete profiles generally cannot save supplier calls. The strongest eligible comparator is the lowest mean configured variable cost with exact outcome agreement, no compulsory skips and virtual p95 <=500ms. Paired differences compare identical rows; 95% intervals use a normal approximation and are descriptive at small counts.

`virtual_time_estimate` covers the whole cohort with configured 10/20/30ms source durations, 200ms transport timeouts, synthetic 1200/2200/3200 microrand prices and a configured 10 microrand/ms runtime rate. `measured_http_engine_only` uses actual delayed HTTP and wall-clock engine runtime for at most the first 20 rows. Strategy order rotates to reduce fixed warm-up bias. Supplier cost remains simulated in both modes. No benchmark reports actual cloud expenditure or MTN savings.

Measured HTTP duration excludes authentication, API routing, persistence, browser overhead and cold starts. These results cannot certify the full warm API <=500ms target. Real source latency can vary due to scheduling; compare repeated runs on a controlled host. CI correctness checks should not assert noisy measured timing. Large jobs are context-cancellable and bounded by API worker timeouts; every started call stays charged when cancelled.

The report retains per-strategy/profile metrics and explains gates honestly. A 20% virtual saving is only a synthetic research target; it is not proof of commercial benefit. No live provider adapters or cross-request evidence cache are enabled.
